## 已实现

1. **403 处置**：仅实际 BPS HTTP 执行器标记可信来源。通用 JSON/HTML/WAF 403 返回脱敏、请求级错误，禁止当前请求重放和自动切换；模型、认证、计费、限流、安全拒绝保留各自语义。账号可选择发生通用 403 时仅关闭该账号 BPS 路径；默认关闭此自动策略，以凭据代次与策略 revision 双重 CAS 防止旧请求覆盖人工操作，不惩罚 native 路径，不触发 OAuth 重登。
2. **模型和管理**：全局及账号策略使用原有设置、账号路由与批量入口。账号支持 inherit/all/selected，selected 空集合明确表示不走 BPS；最终映射模型同时满足全局、账号及 Key 权限。大小写和合法日期快照匹配保持前后端一致。配置本实例保存后生效，其他实例通过约 2 秒周期重新读取数据库同步；模型同步不伪造能力证据。
3. **图片中转**：全请求预检、PNG/JPEG/GIF/WebP 实际格式检查、单图 20 MiB、20 张/请求、解码后图片合计 32 MiB、64M 像素；复用原生 128 MiB 默认请求内存预算及 32 个无排队准入槽。真实入口默认仍为 48 MiB，界面如实展示。
4. **图片生命周期**：原生存储和数据库原子配额，1 GiB/512 张包含预留、未完成写入与待删除对象；按账号和 Key 的散列作用域去重。最后成功引用后保留 30 分钟，热禁用/配置撤销后旧链接失效，重新启用不能复活。读取采用流式 no-store/nosniff，临时输入图从生图画廊排除。删除失败保留配额并延迟重试，避免失败对象阻塞后续清理。
5. **缓存计费**：仅实际 BPS 且账号启用时把缓存创建按普通输入计费；总 input 不重复相加，缓存读保持，所有缓存写入别名及细分统一归零。账单、日志和各下游协议共用归一化结果。合成验证 input=1000/read=100/write=200：关闭时普通输入 700；开启时普通输入 900、write=0，input 仍为 1000。
6. **智能运维及界面**：四类 BPS 事件接入现有告警与 Bark 通道，按账号/凭据代次/类别去重与冷却；默认不执行真实通知或自动恢复权限。已批准的全局图片设置、账号策略、批量设置、原因和恢复状态已实现，中/英/繁体同步；运维事件行和翻页合并包含凭据代次。
