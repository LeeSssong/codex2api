# 凭证运营与首次 2FA 登录

本功能管理上游 OpenAI 账号。入口为「账号管理 → 添加账号 → 2FA 登录导入」及侧栏「凭证运营」。当前分支包含实现，生产发布状态以实际部署记录为准。

## 首次导入账号

1. 打开「添加账号」，选择「2FA 登录导入」。
2. 首次使用点击「一键启用加密」。应用会把独立密钥原子保存到持久数据目录，无需重启。
3. 单个账号填写邮箱、登录密码、验证器绑定的长期 TOTP 密钥。未启用 2FA 时留空；六位验证码不能作为长期密钥。
4. 选择登录出口和账号分组，点击「登录并导入」。批量导入支持最多 100 条三字段文本、CSV 或 JSON。
5. Worker 登录成功后，服务器在同一提交链中完成账号身份去重、凭据写入、登录资料加密保存及凭证运营登记。可在「任务记录」查看结果。

文本格式为每行 `邮箱----密码----2FA密钥`。密码包含分隔符或换行时使用 JSON，例如：

```json
[
  {
    "email": "demo@example.invalid",
    "password": "example-password",
    "totp_secret": "JBSWY3DPEHPK3PXP"
  }
]
```

示例账号与密钥仅用于说明格式。页面提交确认后清除明文，任务输入加密保存在服务器；关闭窗口后任务继续执行。失败或取消的登录任务可从「任务记录」重试，复用服务器保存的资料。重复提交使用幂等键，成功任务重试返回既有结果。

## 登录与巡检

凭证运营包含巡检账号、任务记录、巡检规则和运行设置。已有 OpenAI OAuth 账号可通过「添加现有账号」配置密码/TOTP 或邮箱验证码 API 地址。

- 支持立即巡检、立即重登、批量重登、暂停/恢复、自动重登开关和移出巡检。
- 默认每 1800 秒巡检，鉴权失败后每 300 秒复检，连续 2 次确认失败后排队重登，自动重登冷却 1800 秒。
- 网络、代理、限流、上游临时错误以及模型/套餐拒绝独立记录；不能仅凭 403 就认定登录失效。
- 页面展示密码/TOTP 配置情况、最近/下次巡检、最近重登、冷却、阻塞原因及 Worker 能力。

账号操作菜单也提供立即重登、登录配置和 2FA 管理入口。移出巡检保留普通账号与登录资料；暂停自动任务使旧巡检结果失效，避免关闭后仍被旧结果重新排队。

## 引擎、Worker 与出口

默认使用本地 Worker。账号可跟随全局引擎或单独指定；切换全局引擎影响随后领取的继承任务。Session Studio 需要显式配置 HTTPS 地址和鉴权头，界面会说明邮箱、密码与 TOTP 密钥将发送给所配置服务，使用该服务出口。

邮箱验证码流程、Excel 授权与 2FA 更换使用本地 Worker。并发范围为 1–16，默认 3；减少并发时等待在途操作完成。

本地登录支持账号绑定出口、指定静态代理、直连及独立 Mihomo 托管节点池。有固定绑定时禁止静默直连或改用其他出口；配置、绑定或凭据发生变更会拒绝旧任务回写。

Mihomo 设置接受 Clash `proxies` YAML/JSON 节点，节点资料加密保存。可安装摘要校验后的固定版本 Linux 内核，或指定已安装的可执行文件。每次登录使用独立进程和固定节点，任务结束后释放，配置修改需等待租约结束。

运行包构建、托管和独立 Worker 配置详见 [Worker 使用说明](../tools/credential-runtime/README.md)。托管模式使用版本与文件摘要校验的应用自有运行包。独立 Worker 使用专用随机 token；使用本机 Mihomo 监听器时需共享应用网络命名空间。

## 2FA 更换、恢复与导出

「2FA 管理」提供更换绑定、验证新密钥、验证原密钥及显式导出。

申请候选密钥后，先完成本地加密日志 fsync 和数据库同步提交，再允许一次激活。新会话验证新密钥可用、旧密钥被明确拒绝后才采用新绑定。网络中断、结果不确定或 Worker 消失时保留新旧资料，并阻止重复更换与普通重登；恢复入口只验证已有密钥。

导出可选择当前、候选或原凭据，支持本地生成验证器二维码、密钥、JSON 和三字段文本。默认不包含密码；密码含分隔符/换行时使用 JSON。关闭窗口后清除展示明文并忽略迟到响应。仅管理员可读取显式导出，响应禁止缓存。

备份需要同时保留数据库、`secrets/credential-operations.key`、Worker token，以及完整恢复日志目录和其中的独立 `key.bin`。已有密文但原密钥丢失时，系统拒绝重新生成替代密钥。恢复数据库或回退二进制不会撤销上游已完成的 2FA 更换。

## Codex 与 Excel/BPS 授权

同账号分别持有 Codex 和 Excel grant。合格付费母账号启用 BPS 且保存本地登录资料后，后台可为缺少授权的账号排队获取 Excel grant。Excel 获取失败至少冷却 30 分钟；同账号登录和 2FA 操作互斥。

BPS 使用独立 Excel grant，普通 Codex 继续使用主授权。Excel 刷新在消费单次 refresh token 前先记录持久状态；并发/迟到失败仅影响对应代际。Excel-only 主授权不能被送往原生 Codex 入口。历史未配置凭证运营的账号沿用既有通道行为。

## 验证方式

自动化验证使用虚构账号和本地协议响应，覆盖首次导入、身份去重、加密、重试、租约/配置/出口代际、2FA 故障恢复、双授权隔离和界面交互。真实上游首次登录、重登、2FA 更换、Session Studio 与 Excel 授权需要隔离账号逐项验收；离线通过不能替代这一步。
