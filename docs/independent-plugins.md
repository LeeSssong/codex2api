# Codex2API 独立智能运维插件

Codex2API 自己拥有代码、账号、数据库、缓存、配置、凭据、任务、日志和部署制品。Sub2API 仅是移植时的源码参考；运行、更新和停用 Codex2API 不需要 Sub2API 在线。禁止把 Sub2API 的数据库、Redis、worker 或管理员凭据配置为本应用的依赖。

## 模块与更新边界

插件管理入口为 `/admin/smart-ops/plugins`。每个模块有独立开关、版本、来源和兼容接口标识；安装版本由构建决定，不能通过管理接口任意改写。

| 模块 | 职责 | 更新方式 |
| --- | --- | --- |
| 自动配置 | 新账号默认配置、模型规则、并发升级 | 独立源码模块，随宿主构建发布 |
| 优先调度 | 对已符合原生资格的候选账号评分 | 独立源码模块，随宿主构建发布 |
| 质量运维 | 定时质量检测、处置与恢复 | 独立源码模块，随宿主构建发布 |
| 账号运维 | 原生请求异常观察、告警与恢复记录 | 独立源码模块，随宿主构建发布 |
| 凭证守护 | 令牌巡检及配置的修复动作 | 独立源码模块，随宿主构建发布 |
| 凭证运营 | 加密登录配置、首次导入、任务及自动巡检 | 管理接口随宿主构建；登录执行器独立镜像发布 |
| 鹈鹕测智 | 原生分组调度、计划、测试与费用历史 | 独立源码模块，随宿主构建发布 |

编译式模块可独立修改、测试和启停，但修改 Go 代码后仍需要构建宿主。这里不提供任意上传 Go 动态库或前端脚本的执行入口。登录执行器可在兼容 `plugins/v1` 的宿主上单独替换，不重启 API、数据库、Redis 或其他应用。

停用模块保留配置与历史，并阻止新的自动操作；执行中的任务必须在发布结果前检查取消、插件状态及账号版本。模块开关不代替模块内部的规则开关，安装不会自动启用未配置的告警收件人或自动重登规则。

## 账号与凭据

首次 2FA 登录验证成功后才通过原生账号表进行身份去重、创建或更新；失败登录不能产生可调度的空账号。密码、TOTP 与取码地址用 Codex2API 专属密钥加密。API 返回配置是否已填写，不返回秘密原文。

运行环境使用 `/opt/codex2api/secrets/credential-app.env`（应用加密密钥与专用 worker 令牌）和 `/opt/codex2api/secrets/credential-worker.env`（仅 worker 令牌）。两个文件均为 `0600`，不纳入 Git。worker 不获得管理员密钥或数据库密码。它通过 `/api/internal/credential-ops` 的专用认证领取、续期及完成任务。

`tools/credential-runtime/dependencies.json` 锁定登录引擎源码；`build_credential_runtime.py` 从锁定版本创建独立镜像。该镜像不挂载或调用 Sub2API 的运行容器。查看 worker 的 README 获取实际支持的登录引擎、环境项与诊断方式。

## 后续从 Sub2API 移植新功能

`plugins/ports.json` 记录参考来源提交及每个模块关注的路径。执行以下只读比较：

```bash
python3 tools/port_sync.py --source /path/to/separate/sub2api-checkout --to HEAD
```

报告列出每个模块的候选变化和未映射路径。未映射的公共账号、调度、计费或数据库改动也可能影响适配，需要结合调用关系检查。工具不会自动复制代码、更新基线或修改来源仓库。

移植顺序是：固定来源 SHA → 在 Codex2API 独立分支适配 → 运行模块测试与宿主接口测试 → 更新版本与来源记录 → 提交并推送 → 独立构建和发布。只有确认本轮来源变化已处理后才能前移 `source_commit`。保留各模块 SOURCE 和许可证记录。

## 发布与回滚

宿主发布继续使用 `deploy/release/release_build.py` 与 `release_host.py`。有数据库迁移时，仅 Codex2API 进入维护、排空请求、备份并迁移；数据库恢复能力先在隔离库演练。脚本校验非目标容器的 ID 与启动时间，并拒绝改动 Codex 域名之外的入口配置。

独立执行器更新使用 `build_credential_runtime.py` 构建，再由服务器 `update_credential_runtime.py` 更新已安装的 `credential-runtime` 服务。更新器校验来源、接口版本和不可变镜像，保留旧镜像与配置；失败恢复旧执行器。它不执行数据库迁移，也不调用应用重启或 Sub2API 发布链。

所有发布必须从干净、已推送且与远端一致的 `main` 源码构建。制品标签、digest、测试证据和一次简短发布记录共同构成可核验来源。不要把模拟上游测试称为真实账号登录验收。
