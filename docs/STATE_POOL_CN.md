# State 批量获取与跨主机复用

Docker 镜像：`ghcr.io/hloolx/codex2api:latest`。单容器部署、面板填写和三步迁移见 [Docker 部署与 State 复用快速教程](DOCKER_STATE_QUICKSTART_CN.md)。

## 入口与批量获取

开发页面：`http://127.0.0.1:5173/admin/state-pool`。
部署后入口：管理后台的「State 管理」。

1. 选择已导入的 OAuth 账号。
2. 勾选 Sol、Terra、Luna、GPT-6 Astra 中需要的模型。
3. 在「采集出口」选择日常业务出口，或勾选一个至多个代理。选择「并发竞选」或「依次尝试」，设置每组候选数量；默认 3 个。
4. 设置总并发、单账号并发、单代理并发，默认分别为 4、2、2；点击「批量获取」时一起保存。在「采集任务」展开候选，可查看每个账号、模型、代理和 Session 的独立进度。
5. 通过捕获和复验后，条目出现在「已保存 State」。默认自动启用，并开启到期阻止新请求。

当前精确模型为 `gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`、`gpt-6-astra`，推理档位固定为 `high`。可选模型不代表所有账号都有使用权限。返回模型与请求模型不同会判为失败，不会自动降级替换。

一次最多创建 128 个账号/模型组合，每组 1–12 个候选，最多 1536 个候选；队列最多 2048 个活动候选。20 个账号 × 4 个模型 × 3 个候选可以一次提交。重复活动组合会跳过。总并发允许 1–32，单账号允许 1–4 且不超过总并发，单代理允许 1–8。任务还受业务账号的并发、RPM、可用状态和模型冷却约束，因此实际并发可能更低。任务与结果存储在数据库中；服务意外停止后，失去租约的运行任务会标为中断，不会无限重试。

## 多代理与动态 IP

一个账号/模型是一组，候选按所选代理轮流分配。并发竞速受三层并发限制；逐个尝试仅限制组内串行，其他模型或账号仍可同时运行。任一候选捕获通过后，携带原始 State 回到该账号配置的日常业务出口复验。复验通过才保存，并取消同组其他候选。采集不会修改账号日常代理绑定。

用户提供的 `host:port:username:password` 需要在「代理管理」转换为标准 URL，例如：

```text
http://YOUR_USER-res-country-us-session-1664661000:YOUR_PASSWORD@gate.ipdeep.com:8082
```

用户名或密码含特殊字符时应使用 URL 编码。代理凭据保存在本机现有代理配置中，不进入迁移包或 State 任务列表。

选择含 `-session-...` 用户名的 IPDeep 代理后，页面提供「动态代理每候选新会话」，默认开启。每个候选生成独立的十位数字 Session，只替换用户名的 session 字段，保留密码、国家及其他选项；使用独立连接。普通代理不改写。所有 Session 仍共用原代理的并发预算，复验使用日常业务出口。关闭该开关会使用已保存的原用户名，但依然新建连接。

代理服务可能按连接轮换、保持 Session、或重复分配出口，不能承诺每次新连接或新 Session 一定得到不同 IP。「合并已知相同 IP」只依据普通代理上次测试结果，动态网关不会因为一次历史 IP 被合并，也不会把历史 IP 显示为当前候选的实测 IP。当前没有观测到模型请求本身的实际出口地址。

建议十几个账号先使用总并发 4–8、单账号 1–2、单代理 2–4、每组 3 个候选。单组最坏需要 6 次生成；增加候选会增加额度消耗。账号出现 401、403、429、撤销或冷却时，本轮该账号的其他模型及代理候选一并停止。

### 采集前置代理

如果本机无法直接连接动态代理网关，可以在「采集前置代理」选择另一个已配置代理。例如，本机经 `http://127.0.0.1:9000` 连接 IPDeep，IPDeep 再连接上游：

```text
本机 → 前置代理 #1 → IPDeep #2（独立 Session）→ 上游
复验：本机 → 账号日常业务出口 → 上游
```

选择前置代理后，它会从采集代理勾选列表移除。前置和最终采集代理都参与单代理并发限制，原子预留两段容量，避免大量候选挤满一个前置出口。HTTP、HTTPS 和 SOCKS5 代理均可使用；HTTPS 证书验证保持开启，认证仅发给各自对应的代理。连接失败时不会静默改成直连。代理被删除、禁用或修改后，排队候选会停止，不会继续使用旧配置。

API 在原有采集请求上增加 `forward_proxy_id`；默认 `0` 表示无前置代理。该字段只影响采集，目标机器导入迁移包仍用目标账号的日常出口验证。

页面会在当前浏览器记住账号、模型、代理、前置代理、候选数、策略与复用开关；本地存储不包含 State 原值、OAuth 凭据或代理密码。切换主机不会带走这些本机代理配置。

## 跨主机复制

推荐使用「复制迁移包」：

1. 源机器点击「复制有效 N 项」，也可勾选条目后只复制所选项，或下载 JSON 文件。每次最多 128 条。
2. 目标机器运行包含本功能的 Codex2API，并已导入同一上游成员、同一工作区的 OAuth 账号。
3. 在目标机器的「State 管理 → 导入 State」粘贴迁移包，先查看逐条账号匹配、过期与可复用状态，再导入可用项。
4. 目标机器会使用自己的账号凭据和代理出口复验，通过后自动启用。

迁移包不包含 OAuth access token、refresh token、代理密码或源机器数据库账号 ID。账号使用上游成员与工作区的摘要匹配，因此两台机器的本地账号 ID 可以不同。找不到匹配账号、匹配有歧义、过期或重复的条目会显示原因并跳过，其余条目可导入。若同一原值已在本机相同身份与出口下验证且未过期，可直接复用本地记录，无需再次生成，且不延长原始有效期。

条目的「复制原始 State」可复制原值。原值没有可读的账号、模型或到期信息；使用「原始值」导入时，必须明确选择目标账号、模型并填写**首次捕获时间**。原值模式无法自行证明来源身份，填写者需提供正确绑定，程序仍会执行本地复验。跨主机建议使用完整迁移包。

迁移包含可复用的 State，应按敏感数据保管。复制不会自动传输到其他主机。目标机器需要正常网络和上游账号权限，导入复验会消耗该账号额度。

复制的迁移包使用紧凑 JSON，只携带匹配身份、精确模型、原值、指纹和原始时间等必要字段，不再附带完整答案和本机代理记录。验证记录仍保留在源机器页面中；下载文件保留缩进以便阅读。旧版本包含验证记录的迁移包仍可导入。

## 复用与到期

- 自动复用匹配本地账号、精确模型、`high` 档位；HTTP 请求头和 WebSocket 每条请求的 `client_metadata` 都会注入原值。
- 已有原生续接 State 优先保留；已知属于其他账号或模型的池内 State 会被拒绝。
- 首次捕获后最多保留一小时。后续响应返回的新值不会覆盖原值，复验和迁移也不会重新计时。
- OAuth 凭据、工作区或配置的代理出口发生变化后，原条目失效，需要重新获取或导入复验。
- 开启「到期阻止新请求」时，已启用条目到期或绑定变化会对匹配的新请求返回 503。关闭自动复用后恢复普通请求行为。
- 当前没有定时自动补充任务；到期前可以点击「重新获取」。成功后替换该账号和模型的旧条目，失败会保留旧记录及其原始到期时间。

一小时是本地保留策略，不是上游有效期承诺。此功能支持跨主机迁移和目标出口复验，不保证上游一定接受任何一次迁移。

## 判分与限流

每个新候选最多执行两次生成：先捕获，再携带原值复验。捕获题明确允许按手感选择糖果形状，检查总数 21、圆形 9、五角星 12；程序独立穷举组合核验保证条件和最小值。复验同时包含该题与三道独立问题，要求结构化结果全部正确。

通过还必须满足 HTTP 成功、获取非空 State、收到完整完成事件、返回精确模型一致。HTTP 200 后的 overload、错误事件、残缺流、错误答案均不通过。推理说明会保存供查看，但当前没有自动语义核验推理过程。

429 会接入原有账号/模型冷却逻辑，尊重上游 `Retry-After`；即使超过五分钟也不截断。流式限流同样显示最早重试时间。该账号本轮候选全部停止，不通过切换 State 或代理继续重试。401、403 和停用工作区会停止相关尝试。

“已验证”只表示本次题目和原值复验通过，不能证明模型能力提高或持续不降智。State 不增加额度，也不解除账号限流。
