# 账号并发升档

在「智能运维 → 自动配置 → 并发升级」选择账号分组并启用。它独立于「新账号默认配置」开关，适用于所选分组的新旧账号。新配置默认关闭；升级已有安装保留已保存的开关和参数。

默认连续成功 20 次提升并发 1，最高并发 100，失败或升档后冷却 60 秒，参数可调整。达到上限后不继续累计。已有账号高于上限不会被降低。

只统计 HTTP 文本生成请求：Responses、Chat Completions、Messages、Gemini generateContent/streamGenerateContent。后台探测、WebSocket、压缩、图片、视频和 count tokens 不统计。成功必须完成响应并交付；HTTP 200 的断流不算成功，客户端取消不加成功。同一次请求在同一账号有失败后重试成功，仍只计一次失败；换号后的成功可单独计一次。

失败清零进度并冷却，不自动降档。健康层级、配额、智能配速和 API Key 并发限制仍控制实际准入。升档改变账号级基础并发覆盖值；此前继承全局或分组并发的账号，首次升档后也会生成账号覆盖值。

配置版本、插件启停代次、请求开始时间和当前有效并发共同隔离旧请求。手动调档开始新一轮观察并冷却。重新保存规则只统计新规则发布后开始的请求。关闭功能停止后续升级，不还原已提升的并发。

每次进度和并发更新在同一数据库事务内提交，PostgreSQL 用账号/配置/分组行锁保护，多实例经调度 outbox 更新缓存。复用已有 smart_ops_concurrency 表，不新增数据库字段；兼容旧 JSON 字段。

请求收尾只投递有界队列。队列溢出、配置读取或存储失败会暂停本实例升级，后台显示原因；排除故障后重新保存配置恢复。服务重启后每个账号第一次结果清零旧成功次数，保留冷却和已提升并发。本实例最多跟踪 4096 个账号的重启标记，超过时暂停并提示，避免错误重置已跟踪账号。

账号列表显示每档成功次数、下一档和冷却；关闭或状态未知时隐藏，暂停时展示暂停提示。GET /api/admin/smart-ops/concurrency-progress?ids=1,2 需要管理员认证，单次最多 200 个不同正整数账号 ID；前端对大分页分批查询。

本地验证采用合成账号、本地 HTTP 上游与独立 PostgreSQL，不请求真实模型或改动生产账号来制造升级样本。
