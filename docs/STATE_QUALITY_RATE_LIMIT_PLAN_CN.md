日期：2026-09-17，Asia/Singapore。

## 2. 拆成三个独立维度

1. **访问资格**：凭据是否有效、工作区是否可用、目标模型是否被允许。
2. **服务可用性**：额度、请求速率、并发、模型容量、代理连接是否正常。
3. **回答质量**：在一致且无歧义的任务下，完成的回答是否符合独立评分标准。

state 是实验变量，不作为认证、额度或能力等级证明。长度、响应耗时、思考 token 数和偶然答对都只能作为附加观察。

账号状态和实验状态应分别存储。例如：一个账号可以是“额度冷却中”，其历史质量结果是“通过”，但此刻不能继续发请求。

## 3. 429 与相关错误的分类策略

| 分类 | 判断证据 | 处理 |
|---|---|---|
| 本地限流 | Codex2API 本地限流器或队列的来源标记 | 检查本地 RPM、并发和队列；合理排队，不把错误归给上游账号 |
| 额度耗尽 | `usage_limit_reached`、明确的 5h/7d 窗口或重置时间 | 暂停该额度作用域，按服务端重置时间恢复；可调度其他确有可用额度的授权账号 |
| 短时限速 | `rate_limit_exceeded`、`slow_down`、裸 429，且无明确额度耗尽证据 | 降并发、平滑发出请求，遵守有效 `Retry-After`；缺少提示时指数退避加随机抖动 |
| 模型容量不足 | `server_is_overloaded` 或明确的模型容量错误 | 暂缓该模型或相关路由；不评分为“答题错误”，不直接认定账号被降智 |
| 代理或边缘层拒绝 | 代理 CONNECT 失败、网关 HTML、错误来源和正文类型不匹配 | 单独记录网络/代理故障，验证出口；不要把所有 429 都写成账号额度耗尽 |
| 凭据或访问问题 | `token_revoked`、`deactivated_workspace`、其他明确访问错误 | 停止该作用域测试，按实际错误恢复凭据或访问资格 |

HTTP 200 仅代表流建立成功。还必须解析 SSE/WS 中的最终完成事件和错误事件。已经向客户端输出内容的请求，不应自动完整重放，以免重复输出、工具执行或计费。

### 现有实现及需要调整的点

- `proxy/handler.go` 的 `classify429RateLimit()` / `Apply429Cooldown()` 已区分额度窗口、模型容量和账号临时限流。
- `auth/transient_rate_limit.go` 已有约 15、30、60、120、240、300 秒的本地退避，以及同一冷却窗口内并发 429 的合并处理。
- **当前实现同时把上游 Retry-After 压到最多 5 分钟。** 若服务端要求等待更久，可能提前再次请求。
- 建议只限制本地退避阶梯，不缩短有效服务端等待提示。服务端提示超过任务愿意等待的范围时，返回可重试信息并延期任务，而不是提前重试。
- 增加正向随机抖动，不能减短服务端指定的最早重试时间。
- 统一客户端、网关、质量检测和 state 采集器的重试预算；每个逻辑请求有总尝试次数，防止多层重试相乘。
- 资格、额度、网络、容量和质量分别计数；展示原始上游状态与客户端最终状态，因为代理可能把上游 429 改写为池级 503。

### 探测应共享业务调度预算

默认改为每个账号最多一个在途诊断请求，诊断队列优先级低于业务。存在 429 时不启动该账号的 3 路候选竞赛。

原“并发 3、候选最多 12”可以保留为显式实验模式，只有认证、额度和串行基线均正常时才使用。候选、复验和重试都计入同一个请求预算；不能把 12 个候选误当成最多 12 次上游调用。

同一工作区发生明确停用错误时复用现有工作区联动隔离。不同成员是否共享某项额度必须有证据，不能仅因工作区相同就假定所有限速维度完全相同。

## 4. 回答质量的判定

### 消除糖果题歧义

“可以按形状选择”与“完全随机摸取”应成为两道不同测试，分别评分：

- **形状可选择版**：明确写出“不放回；允许按手感挑选形状但不能辨别口味；须预先确定两种形状各取多少”。最优总数 21，对应圆形 9、五角星 12。
- **完全随机版**：明确不允许按形状筛选。最多可以先拿 28 颗仍不配对，保证数为 29。

正确答案只用于判分，不放进模型输入。现有只比较“最终答案：21”的规则应升级为检查总数、取法及其可行性；缺少可解析结构时标记人工复核，不直接判定降智。

形状可选择版可要求模型输出 `total`、`round_count`、`star_count` 与论证。程序用独立穷举器检查：

1. 数量为整数、未超库存、两种数量之和等于总数。
2. 对该取法的所有合法口味组合，均存在目标配对。
3. 更小总数不存在保证成功的预选取法。

这样可以验证结论和方案，但不能因此宣称自动审核了所有自然语言论证。

### 不依赖单题选优

增加数道独立可核验题，覆盖算术、组合约束、指令遵循和小型代码任务。将候选筛选题和最终留出题分开。

固定成员、精确模型、推理档位、题目版本、工具开关和业务出口。保存全部失败与成功记录，分别报告：完成率、完整回答条件下的正确率、总请求通过率。

多次尝试直到答对本身会产生选择偏差。例如每次只有 10% 的偶然通过率，独立尝试 12 次，至少一次通过的概率也约为 72%。选出一个成功样本不能证明 state 带来了提升。

## 5. state 实验如何接入 Codex2API

当前 `proxy/codex_turn_state.go` 做的是原生 turn-state 透传与跨账号回带剥离；其中一小时 TTL 是**来源记录的本地保留时间**，不是上游 state 有效期保证，也不是已经实现了一小时高质量 state 池。

建议复用现有质量检测任务、账号调度和数据库层，增加一个默认关闭的实验模块：

```text
资格与额度可用
  -> 固定条件的无 state 基线
  -> 低并发获取候选并完成筛选题
  -> 原 state 回业务出口复验
  -> 独立留出题与带/不带 state 的交错对照
  -> 可用于实验的候选
  -> 达到原始过期时间后停用或更换已验证候选
```

具体要求：

- 状态绑定成员、有效工作区、精确上游模型和凭据代次；刷新凭据或切换工作区后要求重新验证。
- 验证记录额外保存推理档位和业务出口配置指纹；出口或关键请求配置改变后重验，不推断上游必然绑定这些字段。
- SSE 在上游响应头采集；WS 检查握手头和 `response.metadata` 的 `headers`。不得依赖客户端一定能收到上游 state。
- 候选与正式请求固定到同一成员，关闭实验请求中的自动换号，否则无法归因。
- 捕获原值与首次时间；复验、业务请求返回的新 state 不覆盖或延长已选候选。
- 本地到期时间不晚于首次捕获加一小时。验证消耗的时间计入这一小时。
- 客户端已有的原生同 turn state 要保留来源和隔离语义，不盲目覆盖。实验 state 注入应限定到显式启用的调用路径。
- strict 模式无合格 state 就暂停该账号模型组合；普通模式遵守原生协议。两种模式在界面上明确区分。
- 到期前可低优先级预验证替代候选；旧候选仍按原期限结束，未取得新候选则暂停。
- 对 `compact`、图片、工具调用、长连接复用及多实例并发单独验收，不能把文本 SSE 的结果外推到所有端点。

带/不带 state 的比较应固定业务出口，交错运行两组并使用独立的新会话。动态代理只用于候选来源；独立 IP 查询不能证明每条生成请求的真实出口相同或不同。

## 6. 建议的实施顺序

1. **恢复可测账号**：重新取得有效凭据，确认工作区可用；当前这 10 条保持已有隔离结果。
2. **补齐错误证据与退避**：保留错误来源、原始 HTTP 状态、终止事件、结构化错误码、Retry-After、重置时间、脱敏请求 ID；修正有效 Retry-After 被截短的问题。
3. **完善质量基线**：拆开两种糖果题，增加独立判分与留出题。先验证当前模型正常表现，再讨论 state 的增益。
4. **小规模 state A/B**：每账号串行起步，固定同一业务出口，保留所有尝试及用量。没有明确收益就不晋升生产使用。
5. **最后接自动更新**：实现候选缓存、持久化、到期停用、低优先级预验证及页面状态。

需重点验证：长 Retry-After 不提前重试、并发错误不造成重试风暴、工作区隔离不串到无关账号、测试不自动换号、state 凭据及模型隔离、重启不续期、流中错误不误判完成。时间边界测试使用可控时钟，不依赖墙钟睡眠。
