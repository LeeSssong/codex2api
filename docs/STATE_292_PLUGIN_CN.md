# 292 State 插件与动态代理采集

入口：管理后台 → State 管理 → 292 State 插件（实验）。默认关闭。

## 最短使用流程

1. 在「代理管理」添加现有动态代理，或者自建 IPv6 HTTP/SOCKS5 代理。
2. 在插件中选择「动态代理池 / 自建 IPv6 代理」，勾选采集代理。多个代理按顺序轮换。需要两跳链路时选择「采集前置代理」。
3. 默认包含全部 OAuth 账号和 Sol、Terra、Luna、GPT-6 Astra；也可以指定账号和模型。
4. 打开插件。全局只有一个采集请求在运行，组合之间轮询，默认间隔三秒。每次使用新连接；IPDeep 可自动生成新 Session。
5. HTTP 200 且 `x-codex-turn-state` 原值长度恰好为 292、编码与时间戳有效时保存；立即取消请求并关闭正文，不等待模型回答。
6. 同一账号、精确模型的业务 HTTP 和 compact 请求覆盖成保存值，并使用直连。WebSocket 每条消息也写入保存值，但旧连接复用仍有下面列出的限制。关闭插件恢复原有出口和 State 管理行为。

采集代理只用于采集。自建代理可以只开放 IPv4 入口，由代理服务器使用 IPv6 连接上游，codex2api 所在机器不需要 IPv6。已有账号代理、全局代理和 Resin 不承担开启插件后的所选模型业务请求；请先确认业务主机能够直连。

没有有效值时，所选账号/模型的业务请求清除客户端带来的 state 后正常直连。到期不再注入旧值，后台重新采集。程序不会因为后续响应返回另一个值而替换未过期的已保存值。

## 有效期与隔离

Fernet 形态 token 中第 1–8 字节的大端时间戳是签发时间，不是过期时间。按用户指定的本地策略：

```text
expires_at = issued_at + 3600 秒
```

不接受过期、未来时间戳、错误版本、非法 Base64 或非 292 字符值。这里只检查结构，无法验证服务端 MAC。一小时不是上游有效期保证。

按上游成员、工作区、凭据版本与精确模型绑定，不按采集 IP 绑定；同工作区的不同成员仍分别处理。推理档位不参与本插件匹配，所选模型各档位均注入同一原值。已知属于其他账号或模型的本插件值被拒绝。

## 跨主机复制

已命中的行提供「复制原始 State」和「复制跨主机迁移包」。推荐后者：目标主机先导入同一成员/工作区的账号，然后打开插件的「导入迁移包」粘贴。

两台主机本地账号 ID 可以不同。迁移包不包含 OAuth 或代理密码，但包含敏感 State。导入重新绑定目标机凭据，按 token 原始时间计算剩余有效期，不续期、不做答题复验。目标机器需打开插件并将该账号、模型纳入作用范围，才会注入。

迁移包的成员/模型标签由导出程序提供，不是服务端签名可验证的归属证明；只导入可信来源的原包。普通 State 池迁移包与本插件格式不同。

## 动态代理与 TunnelBroker

IPDeep：沿用代理管理中的网关 URL，默认开启每次新 Session。网关仍可能重复分配出口，独立连接不等于保证独立 IP。

自建 IPv6 代理：在 Linux VPS 上运行代理服务，给 codex2api 一个 HTTP 或 SOCKS5 URL。无需为每个 IPv6 在面板创建一条代理。代理的随机出口策略由服务端执行。

HE TunnelBroker 的前置条件：VPS 有公网 IPv4，支持 IP 协议 41（6in4，不是 TCP 41 端口），允许必要 ICMP，并已成功创建隧道。使用 Routed /64 或 Routed /48 作为出口地址池；不要把隧道链路本身的 /64 当作可任意分配的路由地址池。

如果创建页面显示 `IP is blocked. (Abuse)`，隧道尚未创建。应通过页面提供的 `ipv6@he.net` 核查受限地址及解除条件，不能靠本插件修复。也可使用现有合法可用的动态代理或 VPS 提供商原生分配的 IPv6 网段。

核对 `seongminhwan/ipv6-dynamic-proxy` 的 `47bf0d5` 版本时发现：`createDialer` 构造的随机拨号闭包未接到返回的普通拨号器，HTTPS CONNECT 与 SOCKS5 路径调用了这个普通拨号器。该版本不应未经修正和出口实测直接投入采集。这里只提供标准代理接入，未部署或宣称修复该第三方服务。

HE 网段中的很多地址仍属于同一网络前缀和运营商。随机地址不保证解除 Cloudflare 拒绝、五秒盾、账号限流或提升模型能力。

## 运行边界

- WebSocket 连接池尚未按模型与 State 版本隔离；`previous_response_id` 续链还可能取回原代理连接。消息字段覆盖已实现，但不能保证所有握手头与实际出口都随插件开关或 State 轮换更新。
- 当前覆盖发往上游的请求，不改写返回客户端的响应 State。上游的新值不替换已保存值。
- 动态代理没有逐请求核实实际出口 IP、IPv6 类型或去重；IPDeep Session 与出口唯一性不是同一概念。
- 模型范围限 Sol、Terra、Luna、GPT-6 Astra；原始值可复制，跨主机导入目前要求迁移包。
- 按 292 长度命中，不做答题判分；响应正文中的 overload、流式 429 或其他后续错误无法在这个模式被观察到。
- 收到 HTTP 401/403/429 会暂停或冷却账号，429 尊重 `Retry-After`；不通过换代理继续重试该账号。
- HTTP 失败不保存 state。网络失败和不匹配结果按计划重试；关闭开关取消正在运行的采集。
- 关闭正文不保证零 token 消耗。开启后后台会持续填补缺失或过期的组合，直至关闭或账号不可用。
- 当前采集调度面向单个 codex2api 实例；多副本应各自使用独立数据库，并通过迁移包交换 State，避免多个采集进程共享调度配置。
- 本机 IPv6 模式只使用已绑定的公网地址，不会自动申请网段、配置 HE 隧道或修改系统网络。

API 位于管理员认证保护下的 `/api/admin/state-pool/ipv6`，GET 查看状态，PUT 保存配置，POST `/export` 和 `/import` 迁移。列表接口不返回原值。
