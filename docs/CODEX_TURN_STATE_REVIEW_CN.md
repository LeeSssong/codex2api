核查日期：2026-09-18。

参考目录：`F:/down/Compressed/codex-turn-state/codex-turn-state`。核查对象为附带的 Go 源码；没有启动附带的 exe，也未验证 exe 与源码是否对应。

## 结论

可以在 codex2api 内实现按账号和模型采集、保存、注入、导出的功能。参考程序提供了 HTTP 请求与响应双向改写的例子，但不满足多账号隔离、一小时失效、头到即停、每次不同 IPv6、WebSocket 每条消息覆盖等要求，不能整体照搬。

该源码把 292 / 312 的含义直接写成规则，没有包含能证明两种长度对应模型能力、上游有效期或跨 IP 接受性的实验。修改响应头也不会改变上游已经生成的回答或消除已发生的 429。

## 程序实际流程

```text
Codex Desktop
  → 本机 127.0.0.1:17890
  → 配置的上游 /v1/responses（默认 CPA 127.0.0.1:8317）
  → 由上游服务选择账号与 OpenAI 出口
```

`main.go` 的 `director` 从 HTTP JSON 正文读模型，改写请求头；`modifyResponse` 改写响应头；`turnstate/filter.go` 用 `map[model]state` 保存值，写入 JSON 文件。

`scan.go` 每轮只接收一个模型和一个 Bearer token。普通扫描默认最多 12 次、并发 4；节点扫描通过 Clash API 切换策略组，每个节点尝试有限次数。命中后停止本轮扫描，后续业务响应仍可更新固定值。

如果上游是远端 CPA，切换本机 Clash 只改变客户端到 CPA 的链路，不能据此认定 CPA 到 OpenAI 的出口改变。多账号采集应放在 codex2api 已选定真实 OAuth 账号之后执行。

## 与需求的差异

| 要求 | 参考程序行为 | 代码位置 |
|---|---|---|
| 账号与模型共同隔离 | 仅按模型索引；不同 Bearer token 共用同模型值 | `turnstate/filter.go:104`、`main.go:186` |
| 固定第一个值一小时 | 新响应的 292 会替换旧值，默认 `replace_pinned=false` 也会 | `turnstate/filter.go:206` |
| 一小时失效 | 没有解析 token 时间，也不检查持久化 `UpdatedAt`；旧记录一直可复用 | `turnstate/filter.go:250`、`:281` |
| 收到头立即中断 | 读到头后继续读取最多 1024 字节正文，可能等到 EOF 或 12 秒客户端超时 | `scan.go:124`、`:353` |
| 只保存成功请求 | 状态码 ≥400 只有在没有 State 时才算错误；429 携带 292 也会固定 | `scan.go:354` |
| 不同 IPv6 出口 | 无 IPv6 地址绑定或出口核实；普通扫描共用 Transport，可能复用连接 | `scan.go:122`、`:207` |
| WS 同账号同模型隔离 | 标准反代只改握手头，不解码 WS 帧；无正文握手默认 Astra | `main.go:140`、`:196` |
| 覆盖消息中的 State | HTTP 正文 `client_metadata.x-codex-turn-state` 原样保留 | `main.go:198` |
| 不干扰业务出口 | 采集和业务使用同一出站代理；切节点删除 Clash 全部连接，结束没有恢复原节点 | `main.go:210`、`scan.go:258`、`clash.go:127` |
| 跨主机复制时校验归属 | 可粘贴原值，但只有长度校验，没有成员、工作区或有效期校验 | `turnstate/filter.go:161` |

此外，普通并发扫描的检查、保存和停止不是一次原子操作，多个已返回的候选可能先后保存，因此“首次命中”并不严格。`discard_length` 参数也没有决定实际丢弃分支：所有非空且不等于 `pin_length` 的值都会被丢弃。

## 离线验证

使用源码的临时副本和合成数据运行测试。原有 9 项测试及新增 6 项审查测试均通过；其中新增测试确认了以下实际行为，而不是证明这些行为符合目标需求：

1. 默认配置也会用新响应替换第一个固定值。
2. `UpdatedAt` 为 2000 年、仅满足长度的非 Fernet 值仍可加载并注入。
3. HTTP 429 携带 292 字符值会被扫描器接受并保存，且扫描器读取了正文。
4. 两个不同 Bearer token 的同模型请求收到同一个固定值。
5. 请求头改写后，正文里的旧 State 没有改写。
6. 无正文的 WebSocket 握手使用 Astra 的固定值。

## codex2api 的实现方向

保留当前服务端采集：按账号与精确模型排队，采集出口独立于业务出口，收到响应头立即取消；HTTP 200、长度与结构及时间符合条件才发布，401/403/429 按状态停止或冷却。

存储归属由账号成员、工作区和精确模型决定。签发时间加 3600 秒是本地策略，导入与重启不能续期。目前凭据变更也会令本地记录失效；若以后允许同身份正常刷新后保留，需要与真正换号明确区分。

可以借鉴参考程序的响应头回写，但必须在最终实际使用的账号与模型确定后查找本地有效值；响应回写不能反向更新未过期的固定值。需要保留上游 HTTP 状态与错误语义。

WebSocket 需要额外把账号、精确模型、State 版本和出口纳入连接复用校验，`previous_response_id` 续链同样校验。不能只重建连接再原样发送旧续链 ID，因为旧响应上下文可能只存在于原连接。无法保留上下文时，应明确要求重发完整上下文或返回可识别的续链失效错误。

出口核实应区分本机绑定、代理提供商的 Session 与真实上游出口。只有自有代理能够记录实际出站 socket 源地址时，才能直接核对该次请求使用的 IPv6；通过另一个 IP 查询请求看到的地址不能证明动态代理给 OpenAI 请求分配了同一地址。

跨主机默认使用含成员、工作区、模型及原始 State 的迁移包；如果增加原值粘贴，必须让用户指定来源账号与模型，并明确程序不能从加密值独立验证其归属。

上述工程功能可实现；实际跨 IP 接受性、整小时可用性和回答质量变化仍需独立验证。
