## 用户可见功能

### 登录与首次导入

- 账号添加入口提供密码/2FA 导入，支持每行 `邮箱----密码----TOTP密钥`、来源已支持的逗号格式和 JSON；一次最多 100 条。包含分隔符或换行的密码用 JSON 无损输入。
- TOTP 指长期密钥，不是一次性的六位验证码；未启用账号 2FA 时允许为空。
- 批量任务逐条展示排队、登录、写入、成功、失败及可重试状态；重试复用已有登录成果，不重复登录或创建重复身份。支持取消与关闭后清除页面明文。
- 成功后走现有账号身份去重与导入链，关联原生代理、分组；将登录资料加密保存并登记凭证运营。首次新增登录也有持久任务，不依赖浏览器持续打开。
- 如接入采购成本，复用 Codex2API 已有实际字段与语义；不另建财务子系统。

### 凭证运营与重登

- 增加“凭证运营”入口：巡检账号、任务记录、巡检规则、运行设置。账号页保留就近的立即重登和登录配置入口。
- 支持现有合格 OpenAI OAuth 账号登记、编辑、暂停/恢复巡检、开关自动重登、移出托管；移出不删除普通账号或未经确认删除已保存配置。
- 展示密码/TOTP是否配置、登录方式、有效引擎、有效出口、最近/下次巡检、连续鉴权失败、最近重登、冷却时间、阻塞原因与任务阶段。普通响应不包含密码、密钥、邮箱取码地址或远端鉴权头。
- 手动立即巡检、单账号立即重登、批量重登。重复点击返回或引用同一活跃任务，不产生并行重登。
- 巡检默认沿用来源规则：正常间隔 1800 秒、鉴权失败复检 300 秒、连续失败阈值 2、自动重登冷却 1800 秒；规则保存重新排期已有启用账号。
- 通过原生账号模型列表请求检查鉴权。缺少令牌、明确 401、可识别的认证错误才累计鉴权失败；403 必须区分令牌无效、模型/套餐拒绝和 Cloudflare 风控，不能一律重登。网络、代理、429、5xx 不累计认证失败。
- PAT、Agent Identity、非 OpenAI 渠道、回收站或不合格账号不进入自动巡检。已有有效账号不能因迁移被重写或自动登录。
- 不恢复独立的旧版凭证守护巡检调度器；其与本次有关的登录服务设置、批量导入与恢复能力整合入同一凭证运营链，防止同一账号被两套任务重复重登。

### 加密与运行设置

- 支持“一键启用凭据加密”，生成独立、随机的 AES-256-GCM 密钥，原子写入持久数据目录 `secrets/credential-operations.key`，文件 0600、目录 0700，无需重启。
- 已有密钥不可覆盖；数据库已有密文但文件遗失时拒绝重新生成。多实例必须使用同一受保护密钥。登录资料与普通账号 token 加密配置分开，不把新敏感资料放入可导出 credentials JSON。
- 支持密码/TOTP 与邮箱 OTP URL 两种方式；取码地址加密保存，保留来源 URL 校验、重定向和私网访问限制。
- 本地 Worker 默认执行；全局/账号引擎选择、Worker 并发 1–16、运行状态、能力、版本和故障原因可见。降低并发等待在途任务完成。
- Session Studio 的 HTTPS 地址和鉴权配置由管理员显式保存。选择前明确提示将发送邮箱、密码和 TOTP 密钥、使用服务出口；不自动切换引擎。邮箱 OTP 和 2FA 更换固定使用本地流程。
- 支持受监督的托管运行包和独立 Worker 两种部署。运行包必须由 Codex2API 自身构建、固定源版本、校验摘要并记录许可证，不在运行时直接依赖 Sub2API 的发布包。

### 2FA 管理

- 账号行提供更换 2FA、状态、验证候选新密钥、验证原密钥和恢复凭据导出。
- 管理员显式显示/导出当前、候选或原凭据；支持验证器二维码、密钥、JSON、三字段文本。默认不带密码，下载使用 no-store，关闭后清除明文并忽略迟到响应。
- 完整继承来源的恢复顺序：旧凭据本地加密保存 → 校验身份 → 申请候选 → 本地 fsync 与数据库加密提交双持久化确认 → 单次激活 → 新会话验证新密钥可登录且旧密钥被明确拒绝 → 原子采用新配置。
- 中断、ACK 丢失或验证不确定进入“待确认”，保留新旧凭据，阻止重复更换、普通重登和旧配置覆盖；恢复按钮仅验证，不能再次 enroll/activate。
- 持久恢复目录与其独立密钥必须随数据库和运营密钥一同备份；旧版二进制回退不能撤销上游已完成的 2FA 更换。

### Codex 与 Excel/BPS 双授权

- 同账号分别保存、刷新 Codex 和 Excel grant；任务显式标记 OAuth profile，验证 client、邮箱、用户及工作区身份。
- BPS 启用条件成立且缺少 Excel 授权时，由有登录资料的合格账号排队获取独立 Excel grant；Codex 授权不被覆盖。失败有冷却，同账号登录与 2FA 任务互斥。
- 适配当前 Codex2API BPS 消费、刷新、401 失效与恢复链。Excel grant 的失效不能清掉新 grant 或停用仍有效的 Codex 授权。
- Excel-only 账号的调度和手工测试必须拒绝误用 Codex 入口；历史 Codex-only/BPS 模式的兼容策略在实现前基于现有凭证形态补充测试，不批量改写存量凭证。

## 原生集成与数据安全

- 使用单独 `credential_operations_*` 表族与增量迁移，必须在既有 `20261017_retire_smart_ops_v1` 完成后初始化；不重新使用被退役清理删除的旧表名。分别覆盖全新库、退役前旧库、退役后库及重复启动。
- 配置、监控、任务、profile grant 和 2FA 恢复记录持久化于 Codex2API 自己的数据库。SQLite 与 PostgreSQL 均支持，约束与领取策略按各自事务能力适配。
- 任务携带 lease、attempt、配置版本、凭证代际、profile 和出口快照；数据库保证同账号活跃操作互斥。旧 Worker、租约失效、取消或过期回调不得覆盖新凭据。
- 凭据回写必须与任务完成、原生身份去重在同一事务或等价可恢复提交链中；提交成功后调用原生 runtime reload 与探测，清除该轮可解除的认证错误状态。
- 本地登录使用当前固定出口绑定与账号代理解析链；明确直连保持直连。有固定绑定时禁止静默切换出口或绕过不可用绑定，冻结 generation 并在领取/提交时验证路由仍匹配。
- 出口能力按来源逐项对齐：跟随账号、指定静态代理、托管节点池。来源的 Mihomo 节点池必须连同节点领取、释放和故障处理适配为 Codex2API 自有实例/适配器；不复用 Sub2API 的节点租约。固定绑定与节点池选择冲突时要求明确配置，不静默覆盖。此项计入迁移验收矩阵，不能仅用一个不可用选项声称已迁移。
- 所有管理员接口使用现有管理端认证，独立 Worker 使用专用随机认证 token、受限内部接口和能力协商；日志、错误、审计、任务快照、子进程参数不泄露明文。
- 实施保留现有工作树改动，使用隔离开发分支；不恢复插件管理、自动配置、优先调度、质量运维、账号告警等其他退役模块。
