# Fixed egress pool — approved design

Implement the user's approved CliProxy/static ISP fixed egress design. A native Codex account explicitly enrolled in a pool receives a durable exclusive proxy resource. Bindings survive restart, inventory synchronization and pool membership changes. Existing accounts remain on current routes by default. Local IPv6 and Resin are incompatible with enrolled fixed egress; reject conflicting enablement. All identity-bearing Codex business, HTTP/SSE/WebSocket, OAuth and maintenance exchanges must use the same binding, fail closed on resource unavailability, and respect explicit request-bound egress exceptions.

Sources: manual static proxy URLs/formats and CliProxy management API. CliProxy online is read-only inventory; start is side-effecting resource creation with durable task/port reservation and no blind retries after ambiguity. Reconcile ambiguous start via online. Stop only individually owned unused resources; no stop-all API exposed. Never call start per business request. Protocol explicit, not inferred from port. Support type 1 host:port, type 2 host:port:user:password, type 3 user:password@host:port with escaped credentials and bracketed IPv6. Use managed port ranges and pool capacity/frequency limits. Existing external resources may be imported but are never stopped automatically. Provider keys/passwords are protected at rest and masked in responses/logs. No live provider credentials are currently supplied: implement/test with fixtures; leave production disabled/unconfigured.

Verified distinct real exit IPs required for exclusive resource assignment. Preserve healthy account bindings during API failure; missing inventory is not deletion. Store stable resource identity separately from observed exit address and provider port. Strict strategy blocks failed binding until recovery/manual switch; stable strategy switches confirmed failed bindings to verified spares, no automatic switch-back. Default connect failures eligible; 407 isolates; upstream 429 and 5xx opt-in; quota/auth/policy/input/client cancellation do not rotate. Bounded aggregate retry budget, no replay after output, no uncertain OAuth replay. Connection reuse includes binding generation. Old failures fenced by expected generation. Existing streams drain before owned resource release. Cooldown never implies remote stop. Default remote auto-stop off. Pool exhaustion never falls back direct or to another pool.
